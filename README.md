# Kangi — JLPT N5 단어장

브라우저에서 책처럼 넘겨 읽는 일본어 N5 단어장. 파일 하나로 돌아간다.

상단바의 **「단어 / 문법」** 으로 두 권을 오간다. 각각 목차·쪽수·읽던 위치를 따로 갖는다.

- **단어 902개** / 23개 주제
- **문법 강의 10편** (단어와 별도) — 동사 활용 ます형 · 〜たい · 〜て형 · ない형 · 자동사/타동사, 형용사 활용 い/な, 조사 は·が / を·に·で·へ / と·や·も·の·から·まで, 그리고 보통형.
  설명 카드 137 + 변환 카드 98 + 짝 62쌍 + 4형태 표 38
- **목차는 N5 / N4로 묶여 있다.** 묶음 머리를 눌러 접고 편다 (접은 상태는 기억된다).
- 모든 단어에 읽기 · 한국어 뜻 · 품사 · 예문 3줄(일본어 / 히라가나 / 해석)
- 일본어 발음 재생, 즉시 검색, 목차, 책갈피
- **예문의 한자에 커서를 올리면 읽기가 뜬다.** 아래 히라가나 줄에서 해당 부분도 같이 밝아진다. 터치 기기는 눌러서 고정.

## 단어 추가하는 법

`index.html` 안의 `const DATA = [...]` 배열만 손대면 된다.

### 일반 단어
```js
{w:"食べる", r:"たべる", k:"먹다", p:"동사",
 e:"昼ご飯はもう食べましたか。",
 ek:"ひるごはんはもうたべましたか。",
 eo:"점심은 벌써 드셨어요?"}
```
`w` 단어 / `r` 읽기 / `k` 한국어 뜻 / `p` 품사 / `e` 예문 / `ek` 예문 읽기 / `eo` 예문 해석

### 새 주제
```js
{ t:"주제 이름", items:[ ...단어들 ] }
```

### 표지 (강의 시작)
**반드시 한 쪽을 통째로 차지한다.** 앞 쪽을 끊고 혼자 한 쪽을 쓴 뒤 새로 시작한다.
표지 쪽에는 러닝헤드를 그리지 않는다 (제목이 이미 크게 있으므로).
**한 섹션에 표지를 둘 이상 둬도 된다** — ⑬편은 N4 부 표지(`no:"PART 2"`)와 강의 표지가 나란히 선다.
key가 `cover|섹션|항목`이라 겹치지 않는다.
```js
{cover:true, no:"동사 활용 ③", t:"〜て형", sub:"~하고 · ~해서",
 lead:"한 문단짜리 소개",
 bullets:["이 강의에서 다루는 것", "…"],
 meta:"설명 13장 · 동사 20개"}
```

### 짝 카드 (둘을 나란히 대조)
라벨(`la`·`lb`)을 데이터에서 받으므로 타/자에도, は/が에도 쓴다.
예문이 둘이므로 `exHTML`에 항목당 서로 다른 캐시 키가 들어간다 (`key+'|a'`, `key+'|b'`).
```js
{pair:true, la:"타", lb:"자", hint:"〜ける / 〜く",
 a:{w:"開ける", r:"あける", k:"열다",   e:"…", ek:"…", eo:"…"},
 b:{w:"開く",   r:"あく",   k:"열리다", e:"…", ek:"…", eo:"…"}}
```
key는 `pair|a.w|b.w`다. **같은 `a.w`+`b.w` 조합을 두 번 쓰지 말 것** — 힌트가 달라도 key가 겹친다.
⑥편에서 「私は ↔ 私が」를 두 장 쓸 뻔했고, 주어를 바꿔(僕は ↔ 僕が) 피했다.

### 문법 설명 카드
```js
{note:true, t:"제목",
 p:["문단1", "문단2"],
 rows:[["行く","行き","行きたい"]]}   // 칸 사이 화살표는 자동
```
**칸 사이의 `→`는 렌더러가 넣는다.** 데이터에 `"→"`를 직접 적지 말 것 —
두 개가 겹쳐 나온다. (두 번 저질러서 지금은 `noteHTML`이 그런 칸을 걸러낸다.)
마지막 칸은 강조색이 붙으므로, 결론이나 정답을 맨 뒤에 둔다.

**`p`의 본문에서만 `**강조**`가 먹는다.** `emph()`가 이스케이프를 건 뒤 별표만 `<b>`로 바꾼다.
`lead`·`bullets`·`rows`에는 파서가 없으니 별표를 적으면 화면에 그대로 찍힌다.

### 활용 변환 카드
단계 수는 자유다. 마지막 단계가 목표 형태로 강조된다.
```js
{conj:true, w:"行く", r:"いく", k:"가다", g:"1그룹 예외",
 steps:[{t:"行く", l:"기본형"}, {t:"行って", l:"いって"}],
 say:"いって",                       // 🔊로 읽어줄 발음
 e:"…", ek:"…", eo:"…"}
```
`g`에는 그룹과 규칙을 같이 적으면 좋다 (`"1그룹 む → んで"`).

### 형용사 활용 카드
네 형태를 표로 깐다. 칸 수는 자유지만 4개(현재·부정·과거·과거 부정)를 전제로 만들었다.
```js
{adjc:true, w:"高い", r:"たかい", k:"비싸다, 높다", g:"い형용사",
 hit:"高いです",                    // 예문에서 실제로 쓰인 형태 — 강조된다 (없어도 됨)
 forms:[["현재","高いです","たかいです"],
        ["부정","高くないです","たかくないです"],
        ["과거","高かったです","たかかったです"],
        ["과거 부정","高くなかったです","たかくなかったです"]],
 e:"…", ek:"…", eo:"…"}
```
각 칸은 `[라벨, 표기, 읽기]`. 🔊는 읽기(3번째)를 읽어준다.
key는 `adjc|단어|읽기`. **네 형태 전부 검색에 들어간다** — 「たかかった」로 쳐도 찾힌다.

**주의 — `adjc`에는 `conj`의 `say` 같은 구분 칸이 없다.** key가 `adjc|단어|읽기`뿐이라
**같은 단어를 두 강의에서 쓰면 key가 겹친다.** ⑩편 보통형은 ⑤편과 같은 표 카드를 쓰는데,
高い를 다시 쓰면 ⑤편 카드와 부딪히므로 **⑤편에 없는 형용사만 골라서 피했다**(面白い · 暑い · 簡単 · 大切).
동사·명사는 ⑤편에 없어 자유롭다. ⑫·⑮에서 셋째·넷째로 다시 썼는데, 그때도 겹치지 않는 단어를 골라서 넘겼다.
다섯째가 오면 그때는 key에 칸을 하나 더 두는 편이 낫다.

**`adjc`는 형용사 전용이 아니다.** 「같은 단어 · N개 형태」면 무엇이든 담긴다.
⑫는 정도 4단(とても / 少し / あまり〜ない / ぜんぜん〜ない), ⑮는 조건 4형(と / ば / たら / なら)을 같은 카드로 그렸다.
라벨 칸이 자유롭기 때문이고, ⑳ 추측 다섯 종류도 같은 손으로 덮인다.

칸 배치는 화면이 아니라 **지면 폭**이 정한다 (`repeat(auto-fit, minmax(178px, 1fr))`).
펼침면에서는 지면이 화면의 절반이라 미디어쿼리로는 맞출 수 없기 때문. 좁으면 알아서 한 줄씩 접힌다.

**주의 — `say`는 강의마다 달라야 한다.** 활용 카드 key가 `conj|단어|say`라서, 같은 동사가 여러 강의에 나올 때(買う가 〜たい에도 〜て형에도 있다) `say`가 겹치면 예문과 책갈피가 섞인다.
### 모드 (단어 / 문법) · 레벨 (N5 / N4)
섹션에 `kind:"grammar"`를 붙이면 **문법 모드** 쪽 책에 들어간다. 안 붙이면 단어 모드.
`lv:"N4"`를 붙이면 목차의 **N4 묶음** 아래로 들어간다. 안 붙이면 N5다.

```js
{ t:"동사 활용 ③ 〜て형", kind:"grammar", lv:"N5", items:[ ... ] }
```

목차는 `LEVELS`(`['N5','N4']`) 순서로 묶음을 그린다. **비어 있는 묶음도 「준비 중」으로 남겨 둔다** —
앞으로 뭐가 들어올 자리인지 보이는 편이 낫기 때문. 접은 묶음만 `kangi-toc-shut`에 저장된다(기본은 펼침).

모드마다 쪽 나눔과 목차가 따로 계산되고, 읽던 위치도 `kangi-anchor-word` / `kangi-anchor-grammar`로 따로 저장된다. 검색과 책갈피는 두 모드를 함께 훑고, 다른 모드의 항목을 누르면 자동으로 그쪽으로 넘어간다.

**주의 — 같은 `w`+`r` 조합을 중복해서 넣지 말 것.** 책갈피 key가 `단어|읽기`라서 겹치면 하나를 찍을 때 다른 하나도 켜진다. 활용 카드는 `conj|` 접두사가 붙어 일반 단어와 안 겹친다.

## 만든 과정 · 결정 기록

시간순. 왜 그렇게 됐는지가 중요한 것들만.
강의 번호는 **그때 기준**으로 적혀 있다. 14번에서 ます형이 ①로 들어오며 한 칸씩 밀렸다.

### 1. 리스트형 단어장 (114단어)
플래시카드·가리기 없이 위에서 아래로 쭉 읽는 형태로 시작. TTS 발음, 주제별 목차.

### 2. 페이징 — 스크롤이 너무 길다
114개를 한 줄로 늘어놓으니 스크롤이 감당이 안 됐다. 책처럼 쪽을 나누고, 넓은 화면에서는 두 쪽 펼침.

처음엔 **10단어 고정**으로 했는데 여전히 쪽 안에서 스크롤이 남았다. →
**화면 높이를 실측해서 들어가는 만큼만 담는 방식**으로 바꿨다. 고정 개수로는 화면마다 안 맞기 때문. `overflow:hidden`이라 스크롤바 자체가 없다.

부작용: 총 쪽수가 기기마다 달라진다. 그래서 「읽던 위치」를 쪽번호가 아니라 **단어 key**로 저장하게 바꿨다.

**iframe 함정** — 창 `resize` 이벤트만 듣고 있었는데, iframe은 크기가 바뀌어도 이 이벤트가 안 온다(실측 0회). Artifact가 페이지를 iframe에 띄우므로 그대로 두면 내용이 잘렸다. `ResizeObserver`로 교체.

### 3. 색 — 네 번 갈아엎음
1. 베이지 + 테라코타 → 시스템이 다크 모드라 계속 어둡게 떴다. `prefers-color-scheme` 참조를 아예 제거하고 밝은 쪽을 기본으로.
2. 흰 종이 + 남색 → **순백은 책 같지 않다.** 종이는 순백을 안 쓴다.
3. 아이보리 → **눈이 편한 녹색으로.**
4. 세이지 녹색 → 색이 옅게 퍼져 흐릿했다. → **초록을 껍데기(상단바·하단바·책상)에 몰아넣고 지면과 글자는 중립색으로.**

최종: 껍데기 `#17795a`, 지면 `#f5f7f4`, 강조 `#00704a`.
**글자에는 색을 안 쓴다** — 예문 해석도 갈색에서 회색으로 내렸다. 색이 아니라 밝기 위계로 구분.

### 4. 902단어로 확장
23개 주제로 재편성. 이때 **책갈피 저장 방식을 순번 → 단어 key로** 바꿨다. 순번이면 단어를 끼워 넣는 순간 전부 어긋난다. 앞으로 N4를 얹어도 안 깨진다.

중복 7건을 잡아냈다. `本`이 「책」과 조수사 「~자루」로 겹쳐서 조수사를 `〜本`으로 분리.

### 5. 히라가나 가독성
예문 아래 히라가나가 잘 안 보였다. 12px인 것도 문제였지만 **투명도 85%를 덮어씌운 게 더 컸다.** 투명도를 걷어내고 14px로.

### 6. 검색 + 문법 강의
902개가 되면서 검색이 필수가 됐다. 가타카나↔히라가나를 맞춰 비교하고 예문 내용까지 훑는다.

〜たい 활용을 예시로 문법 강의 카드 타입(`note` / `conj`)을 새로 만들었다. 반응 보고 넓힐 예정.

이때 **360px 폭에서 상단바가 가로로 넘쳤다** — 검색 버튼이 늘어난 탓. 600px 이하에서는 버튼 글자를 숨기고 아이콘만 남기도록.

### 7. 문법을 별도 모드로 분리
처음엔 문법 섹션을 단어책 맨 뒤에 붙였는데, 성격이 다른 내용이 같은 흐름에 섞였다.
**「단어 / 문법」 두 권으로 분리.** 모드마다 쪽 나눔·목차·읽던 위치가 따로 간다.

검색과 책갈피는 **일부러 두 모드를 함께** 훑게 했다. 「たべたい」를 검색했는데 문법에 있다고 안 나오면 검색의 의미가 없다. 다른 모드 결과에는 「문법」/「단어」 태그가 붙고, 누르면 그쪽으로 자동으로 넘어간다.

모드 전환 버튼이 들어가면서 **상단바가 또 넘쳤다**(393px 필요 / 390px 화면). 브랜드의 N5 배지 → 420px 이하에서 브랜드 자체 순으로 단계적으로 줄였다. **모드 전환만은 끝까지 남긴다** — 없으면 문법에 갈 방법이 없다. 320px까지 확인.

전환 소요: 문법 7–12ms, 단어 155–164ms(902개 재측정).

### 8. 한자 읽기 — 올리면 보이게
예문마다 한자 문장(`e`)과 히라가나 문장(`ek`)을 둘 다 갖고 있다는 점을 이용했다.
**한자가 아닌 부분(가나·기호)은 양쪽에 똑같이 나타나므로** 그걸 기준점 삼으면 사이 구간이 곧 그 한자 덩어리의 읽기다. 사전 없이 순수 문자열 정렬로 해결.

- 한자 있는 예문 894개 **전부 정렬 성공, 실패 0건.** 한자 덩어리 1939개에 읽기가 붙었다.
- 덩어리 단위까지만 나눈다. `毎朝散歩 = まいあささんぽ` 처럼 붙어 있는 건 못 쪼갠다 — 그러려면 사전이 필요하고, 없는 걸 있는 척하느니 덩어리째 보여주는 게 정직하다.

**말풍선은 절대 위치로** 띄운다. 줄 높이를 건드리면 쪽 나눔이 흔들리기 때문. 아래 가나 줄의 대응 부분을 같이 밝히는 건, 긴 가나 중 **어디가 이 한자인지**가 곧바로 보이게 하려고 덧붙였다.

**성능(한자 읽기)** — 스팬 1939개가 늘면서 재분할이 165 → 240ms로 느려졌다.
캐시를 넣어도 그대로였다. 병목은 정렬 계산이 아니라 **측정용 DOM이 무거워진 것**이었다.
그래서 쪽 높이를 잴 때는 스팬 없는 평문으로 그린다. 스팬이 인라인이고 여백이 없어 높이에 영향이 없다는 걸 **928개 전수 비교로 확인**한 뒤에 적용했다 (차이 0건). 결과 143–154ms — 기능 넣기 전보다 오히려 빨라졌다.

### 9. 문법 ② 〜て형 — 카드 구조 일반화
〜たい 카드는 「기본형 → ます형 → たい형」 3단계가 코드에 박혀 있었다. て형은 2단계라 안 맞아서 **`steps` 배열로 일반화**했다. 기존 16장도 같은 형태로 옮겼다.

**키 충돌 버그** — 넣고 나니 買う의 て형 카드에 たい 예문이 나왔다.
활용 카드 key가 `conj|단어|읽기`였는데, 買う는 두 강의에 다 있으니 **키가 같았다.**
예문 캐시가 앞선 것을 돌려주고 있었고, 책갈피도 서로 섞이는 상태였다.
key에 목표 형태(`say`)를 넣어 해결 — `conj|買う|かって` vs `conj|買う|かいたい`.
고친 뒤 961개 key 전수 유일성을 확인했다.

검색 결과도 두 카드가 「買う 사다 활용」으로 똑같이 보여 구분이 안 됐다. 활용 카드는 뜻 대신 **목표 형태**를 보여주도록 바꿨다 — `買う → 買って`.

### 10. 강의 표지
강의가 둘이 되니 쭉 이어져서 어디서 갈리는지 분간이 안 갔다.
**표지 카드**를 넣어 강의마다 한 쪽을 통째로 쓰게 했다. 넘기다 보면 새 강의 시작이 바로 보인다.

쪽 나눔 규칙에 예외를 하나 추가했다 — 표지를 만나면 진행 중인 쪽을 끊고, 표지 혼자 한 쪽을 쓰고, 새 쪽으로 넘어간다.

짧은 화면(320×568)에서 표지가 1px 넘쳤다. flex 중앙정렬의 반올림 아티팩트라 실제로 잘리는 건 없었지만, `max-height:580px` 구간을 추가해 여유를 57px로 벌렸다.

### 11. 단어에도 표지 · 모바일 대응

**단어 23개 주제에도 표지를 넣었다.** 문법 표지가 「무엇을 배우는지」를 적는다면, 단어 표지는 「무엇이 들어 있는지」를 보여준다 — 한 줄 소개 + 대표 단어 4개를 칩으로.

**번호 문제** — 표지를 항목 배열에 넣으면 단어 번호(001~902)가 전부 한 칸씩 밀린다.
표지·설명·활용 카드를 빼고 '진짜 단어'만 세는 별도 번호(`n`)를 만들었다. 목차의 번호 범위와 러닝헤드도 이 번호를 쓴다.

**펼침 기준을 1000 → 700으로 낮췄다.** 폰 가로(844×390)에서 한 면만 쓰면 넓은 화면에 단어 하나만 남아 낭비였고, 태블릿 세로(820)에서는 한 줄이 100자를 넘어 읽기 나빴다. 두 쪽이면 한 면이 320px 이상 확보된다.

**세로가 짧은 화면** — 390px 중 상·하단바가 105px를 먹어 읽을 자리가 없었다.
`max-height:480px` / `400px` 두 단계로 껍데기와 항목을 조였고, 표지는 미리보기·목록을 접는다.

**안전장치** — 아무리 조여도 항목 하나가 쪽보다 큰 화면은 있을 수 있다. 그런 쪽에만 `.scrollable`을 붙여 스크롤을 연다. 조용히 잘리는 것보다 낫다. (현재 확인한 모든 크기에서 0건)

**터치 대응** — `:hover` 규칙을 전부 `@media (hover:hover)`로 옮겼다. 터치에서는 탭한 뒤 hover가 남아 눌린 것처럼 보이기 때문. 한자 툴팁은 `:hover`와 `.on`(탭 고정)을 분리해야 했다 — 합쳐두면 탭 경로까지 죽는다. `@media (pointer:coarse)`로 아이콘 버튼 24→30px 등 표적도 키웠다.

**되짚은 버그 ①** — 320px에서 한 쪽이 9px 넘쳤다. 원인은 가나 강조 스팬 `.kr`의 좌우 패딩 1px. 인라인 스팬의 가로 크기가 달라져 줄바꿈이 바뀌는데, 쪽 높이는 평문으로 재고 있으니 어긋났다. 패딩을 없애고 배경만으로 강조하도록 바꾼 뒤 260~740px 일곱 개 폭에서 986개 항목의 평문/렌더 높이가 전부 일치함을 확인했다.

### 12. 문법 ③ 자동사·타동사 — 그리고 오래 숨어 있던 버그

대조를 보여줘야 해서 **짝 카드(`pair`)** 를 새로 만들었다. 활용 카드는 변환 체인이라 안 맞았다.
타동사(を)와 자동사(が)를 위아래로 놓고 각각 예문을 붙인다. 예문이 둘이라 `exHTML`이 항목당 캐시 키를 둘 받도록 고쳤다.

**측정 폭이 렌더 폭과 달랐다 (오래된 버그)**
`paginate()`가 빈 틀을 **한 쪽만** 깔고 높이를 쟀다. 그런데 펼침면에서는 **두 쪽**으로 그려진다.
즉 1178px에서 재고 589px로 그리고 있었다. 폭이 절반이면 줄바꿈이 늘어 실제 높이가 커진다.

단어 카드는 짧아서 우연히 안 걸렸고, 화면에 보이는 두 쪽만 검사해 왔기 때문에 계속 지나쳤다.
이번 강의의 설명 카드가 길어지면서 63px·23px씩 넘쳐 드러났다.

고친 뒤 **전 쪽 전수 검사**로 확인했다 — 데스크톱·노트북·폰 세로·작은 폰에서 두 모드 모두 넘침 0.
폰 가로 문법 모드에서만 37쪽이 넘치는데, 설명 카드가 224px 높이보다 커서 생기는 것이고 **전부 `.scrollable` 예외로 덮여 있다**(미덮임 0). 잘리는 내용은 없다.

**교훈** — 「보이는 쪽만 검사」로는 부족하다. 이후로는 빈 틀을 깔고 전 쪽을 훑는 방식으로 검사한다.
표지 쪽(`display:flex`)을 측정 컨테이너로 쓰면 프로브가 가로로 배치돼 결과가 엉킨다는 것도 같이 알았다.

### 14. ます형을 ①번으로 — 순서를 바로잡음

원래 문법 순서가 거꾸로였다. 〜たい 강의의 첫 줄이 *"동사를 ます형으로 바꾼 뒤"* 인데,
정작 ます형을 가르치는 편이 없었다. 〜て형도 그룹 판정이 먼저 필요하다. 즉 ①②가 없는 ⑤에 의존하고 있었다.

**ます형 강의를 신설해 ①번에 넣고 기존 강의를 전부 한 칸씩 밀었다.** (①→② … ④→⑤)
설명 13장 + 동사 21개. 1그룹 어미 아홉 갈래를 전부 한 번씩 지나가도록 골랐다.

**용어 충돌을 정리했다.** 〜たい 편은 「ます형」으로 어간(行き)을 가리키고 있었는데,
새 강의는 같은 말로 정중형 전체(行きます)를 가리킨다. 그대로 두면 같은 책 안에서 정면으로 부딪힌다.
- 정중형 전체 = **ます형**
- ます 앞부분 = **ます형 어간** ← 〜たい·〜ながら·〜に行く가 붙는 자리
- 활용 카드 단계 라벨 `l:"ます형"` 16개를 `l:"어간"`으로, 〜たい/〜て형 본문 표현도 같이 맞췄다
- 새 강의에 이 구분만 다루는 설명 카드를 한 장 넣었다 (책마다 다르게 쓰는 말이라 미리 못 박아둠)

**단어 파트는 손대지 않았다.** 902개 그대로. 동사에 그룹·ます형을 붙이는 안은 보류.

**검증** — 활용 카드 21개의 ます형을 규칙으로 따로 유도해 데이터와 대조했다 (불일치 0).
う·く·ぐ·す·つ·ぬ·ぶ·む 여덟 어미 + る→り까지 전부 커버. 다른 강의와 `conj` key 충돌 0.

**같은 실수를 두 번 했다** — 13번에서 없앤 「rows에 "→"를 직접 적는」 실수를 새 강의에서 또 저질렀다.
이번엔 고치는 김에 **렌더러가 걸러내도록** 했다. `noteHTML`이 화살표만 든 칸을 버린다.
데이터에 뭘 적든 화살표가 겹칠 수 없다.

### 13. 문법 ④ 형용사 활용 — 그리고 깃 저장소

동사만 세 편이 이어져 있어서 형용사로 넘어갔다. 규칙 계통이 아예 달라 커버 범위가 크게 넓어진다.
설명 14장 + 형용사 18개. 둘을 가르는 법, 「高いでした」가 없는 이유, いい 불규칙,
〜くて/〜で 잇기, 〜く/〜に 부사, 〜くなる/〜になる 변화까지.

**새 카드 타입 `adjc`** — 형용사의 네 형태는 서로 유도되는 게 아니라 나란히 놓인 선택지다.
동사 활용 카드(`chain`)는 「기본형 → 중간형 → 완성형」이라 화살표가 맞지만 여기엔 안 맞아서, 표로 깔았다.
칸 접힘을 화면 폭이 아니라 지면 폭이 정하게 한 이유는 12번에서 배운 것과 같다 —
**펼침면에서 지면은 화면의 절반이다.** 미디어쿼리는 그걸 모른다.

**같이 고친 것 둘**
- 설명 카드 rows에 `"→"`를 직접 넣은 곳들. 렌더러가 칸 사이에 화살표를 이미 넣기 때문에 두 개가 겹쳐 나왔다. 12개 제거 (〜て형·자동사 강의 포함).
- 짝 카드를 책갈피에 넣으면 목록에 `undefined`가 찍혔다. 짝 카드에는 `w`·`k`가 없고 `tr`·`itr`로 들어있다. `開ける ↔ 開く 「타/자」`로 나오게 고쳤다.

검사는 12번에서 정한 방식대로 — 빈 틀을 깔고 전 쪽 전수 검사.
1920·1366·768·390·320·844×390 여섯 크기, 두 모드 전부 **미덮임 0**.
좁은 화면에서 넘치는 쪽은 전부 `.scrollable`로 덮여 있다.

이 시점에 GitHub(`kes-knows-nothing/kangi`)에 올렸다. 코드 보관 겸, 나중에 Pages로 바로 배포하기 위해.

### 15. 문법 ⑥ 조사 は와 が — 짝 카드를 일반화

**책에 조사를 가르치는 편이 없었다.** ④편이 「を냐 が냐」로 자동사·타동사를 가르는데, 정작 を와 が가 뭔지는 어디에도 안 나왔다. 14번의 ます형과 같은 종류의 역순 의존이라 조사부터 깔았다.

**짝 카드를 일반화했다.** `tr`/`itr`(타동사/자동사)로 이름이 박혀 있고 라벨도 「타」/「자」로 코드에 있었다.
は/が에는 그대로 못 쓰니 위치 이름 `a`/`b`로 바꾸고 **라벨을 데이터에서 받게(`la`·`lb`)** 했다.
검색 결과와 책갈피에 찍히던 「타/자」 고정 문자열도 라벨을 쓰도록 고쳤다.
기존 14장은 `la:"타", lb:"자"`를 붙여 옮겼고, **key 계산식(`pair|a.w|b.w`)은 그대로 둬서 기존 책갈피가 안 깨진다.**

**변화를 단계로 보여주는 카드를 조사에도 썼다.** は/が에는 활용이 없지만, 조사끼리 부딪히는 자리는 활용과 똑같은 「변화」다 —
`を`는 밀려나 사라지고(肉を食べません → 肉は食べません) `に`는 남아서 `には`가 된다.
술어가 바뀌면 `を`가 `が`로도 간다(寿司を食べます → 寿司が好きです). 활용 카드(`conj`)를 그대로 재사용해 9장.

**한국어에 없는 것만 따로 떼어냈다.** は/が는 은/는·이/가와 많이 겹쳐서, 겹치는 부분에 시간을 쓰면 낭비다.
「믿어도 되는 곳 / 안 되는 곳」을 가르는 카드를 앞에 두고, 대응이 없는 셋 — 「초밥을 좋아한다」가 が가 되는 것,
눈앞에서 방금 벌어진 일의 が(현상문), は가 문장 끝까지 걸린다는 감각 — 을 각각 한 장씩 떼어 다뤘다.
앞 강의에 기대는 대목(①ます형 · ③〜ています · ⑤な형용사)은 짧게 되짚는 카드를 표지 다음에 넣었다.

**검증** — key 1122개 전수 유일성 0건 중복, 예문 1042개 후리가나 정렬 실패 0건.
쪽 넘침은 1920·1366·768·844×390·390×844·320×568 여섯 크기 두 모드 전수 검사로 **미덮임 0**.
(Chrome 헤드리스는 창을 500px 밑으로 못 줄여서, 390·320은 그 크기의 iframe에 띄워 쟀다.)

**같이 찾은 것 — 고치지 않음** 폭이 500px일 때 ④편 63쪽이 3px 넘치는데 `.scrollable`로 안 덮인다.
**이번 변경 이전 파일에서도 같은 쪽이 같은 값으로 넘친다.** ⑥편과 무관한 기존 문제라 손대지 않았다.
`avail`의 여유 4px을 늘리면 될 것 같지만 쪽 나눔이 전부 바뀌므로 따로 다뤄야 한다.

### 16. 문법 ⑦ 조사 を·に·で·へ — 그리고 목차를 두 단으로

⑥편이 「무엇에 대해 말하는가」였다면 ⑦편은 「그 일이 어디서 어떻게 일어나는가」다.
설명 15장 + 변화 6장 + 짝 14쌍.

**한국어가 이번엔 꽤 도움이 된다.** 에/에서가 に/で와 거의 그대로 맞고, 「길을 걷다」의 을/를도 「道を歩く」와 같다.
그래서 ⑥편에서 만든 「믿어도 되는 곳 / 안 되는 곳」 카드를 그대로 이어 쓰고, 대응이 없는 둘만 한 장씩 떼어냈다 —
**한국어 「~를」인데 に를 쓰는 동사들**(バスに乗る · 友達に会う · いすに座る · 会社に勤める)과
**ある / いる**(한국어 「있다」 하나가 둘로 갈린다).

**변화 카드는 ①편 회수로 썼다.** ます형 어간 + `に` + 行く → 「買う → 買い → 買いに行きます」.
어간이 어디에 쓰이는지를 ①편 이후 처음으로 실제로 보여주는 자리다.

**목차를 N5 / N4 두 단으로 바꿨다.** 문법이 7편이 되고 앞으로 26편까지 가면 평평한 목록으로는 못 찾는다.
섹션에 `lv`를 붙이고(기본 N5), 목차를 묶음 머리 + 주제 목록으로 그린다. 묶음은 눌러서 접고, 접은 것만 저장한다.
**빈 N4 묶음도 「준비 중」으로 남겨 뒀다** — 앞으로 뭐가 들어올 자리인지 보이는 편이 낫다고 봤다.

**같이 고친 것** 짝 카드에서 표기와 읽기가 같으면(`バスに` 같은 가타카나 항목) 같은 글자가 두 번 찍혔다.
활용 카드에 이미 있던 규칙(`r !== w`일 때만 읽기 표시)을 짝 카드에도 넣었다. ⑥편의 `すしは`·`パンは`도 같이 고쳐졌다.

**검증** — key 1158개 중복 0, 예문 1076개 정렬 실패 0, 쪽 넘침 여섯 크기 두 모드 **미덮임 0**.
(④편 63쪽 3px은 15번에 적은 그대로 남아 있다.)

### 17. 문법 ⑧ 조사 と·や·も·の·から·まで — N5 조사를 닫는다

⑥편이 「무엇에 대해 말하는가」, ⑦편이 「어디서 어떻게 일어나는가」였다면 ⑧편은 「무엇과 무엇을 함께 놓는가」다.
설명 15장 + 변화 6장 + 짝 14쌍. **이걸로 N5 조사가 전량 들어왔다.**

**새 카드 타입은 하나도 안 만들었다.** ⑥·⑦에서 일반화해 둔 `note`·`conj`·`pair` 셋으로 전부 덮였다.
로드맵이 「새로 만들 것은 거의 없다」고 적어둔 대로였다.

**も는 ⑥편 は의 재탕이다 — 그래서 짧아졌다.** も도 を·が를 밀어내고 に·で·と 위에는 겹쳐 앉는다.
규칙이 は와 글자 하나 빼고 같아서, 새로 가르치는 대신 **⑥편에서 쓴 변화 카드를 그대로 다시 그렸다** —
「パンを食べます → パンも食べます」, 「大阪に行きます → 大阪にも行きます」. 앞 편이 뒤 편을 진짜로 줄여준 첫 사례다.

**한국어에 없는 셋만 떼어냈다.** ⑥·⑦에서 정한 방식을 그대로 이었다.
① **と와 や의 갈림** — 한국어 「와/과」 하나가 둘로 나뉜다. と는 「그게 전부」, や는 「그 밖에도 있다」.
② **의문사 + も + 부정** — 何も·誰も·どこにも는 뒤가 반드시 부정이어야 한다. 긍정이면 か로 갈린다.
③ **명사를 대신하는 の** — 「赤いのをください」. ⑤편 형용사 수식의 명사 자리를 の가 받는다.

**경계를 미리 그어뒀다.** から는 두 얼굴(시작 / 이유)이라 둘 다 보여주되 ので와의 대조는 ㉓편으로,
より는 「AよりBのほうが」와 한 묶음이라 ⑫편으로, 「食べるのが好き」의 の는 ㉔편으로 넘긴다고 본문에 적었다.
로드맵의 전제 관계를 카드 안에서 말해두면 나중에 그 편을 쓸 때 되돌아올 자리가 생긴다.

**검증** — key 1194개 중복 0, 예문 1110개(한자 포함 1085) 정렬 실패 0.
쪽 넘침은 1920·1366·768·844×390·390×844·320×568 여섯 크기 두 모드 전수 검사로 **미덮임 0**.
좁은 화면(844×390 · 320×568)에서 넘치는 쪽은 전부 `.scrollable`로 덮여 있다.

**검사 도구를 의존성 없이 다시 짰다.** puppeteer가 없어서 헤드리스 Chrome을 `--remote-debugging-port`로 띄우고
**CDP를 WebSocket으로 직접 두드린다**(Node 24의 내장 `WebSocket`). 창 크기는 `Emulation.setDeviceMetricsOverride`로 주므로
**500px 밑으로도 그냥 내려간다** — 15번에서 iframe을 쓴 이유가 사라졌다.
빈 틀이 아니라 실제 쪽 HTML(`pageHTML(p)`)을 깔고 `page-body`의 `scrollHeight`를 재는 방식이다.

**같이 찾은 것 — 고치지 않음** 폭 500px·700px에서 ⑤편의 한 쪽이 1px 넘치는데 `.scrollable`로 안 덮인다.
**⑧편을 뺀 사본으로 같은 검사를 돌려 쪽 번호·픽셀까지 똑같이 나오는 것을 확인했다.** 기존 문제라 손대지 않았다.
15번의 ④편 63쪽 3px과 같은 계열 — `avail`의 여유 4px 문제로 보이며, 건드리면 쪽 나눔이 전부 바뀌므로 따로 다뤄야 한다.

### 18. 문법 ⑨ ない형 — 조사 셋을 끝내고 동사로 돌아왔다

⑥⑦⑧이 조사 세 편이었으니 ①③에 이어 동사 활용의 마지막 핵심으로 돌아왔다.
설명 14장 + 동사 20개 + **짝 6쌍**.

**①편을 통째로 재활용했다.** 그룹 판정법이 그대로고, 바뀌는 건 「어느 단으로 가느냐」뿐이다 —
ます형은 い단(買い), ない형은 あ단(買わ). 그래서 판정 설명을 다시 쓰지 않고 「①편 그대로다」라고 못 박은 뒤
차이만 한 장으로 보여줬다. ⑧편에서 ⑥편 は를 재활용한 것과 같은 손이다.

**함정 세 개를 각각 한 장씩 떼어냈다.**
① **買う → 買わない** — う행의 あ단 자리가 비어 있어 わ가 대신 들어간다. ます형에는 없던 함정이라 새로 못 박았다.
② **ある → ない** — 어간째 사라진다. 정중형 ありません은 멀쩡한데 보통형만 무너지는 게 헷갈리는 지점이다.
③ **2그룹처럼 생긴 1그룹**(帰る·入る·切る) — ①편의 그 함정이 여기서 다시 걸린다.

**이 편의 핵심은 한 줄이다 — 「ない는 い형용사처럼 활용한다」.**
⑤편에서 배운 高い → 高かった → 高くて가 그대로 ない → なかった → なくて다.
그래서 과거 부정(行かなかった)은 새로 외울 게 없다. 앞 편이 뒤 편을 줄여준 두 번째 사례.

**계획에 없던 짝 6쌍을 넣었다.** 로드맵은 「설명 13 · 동사 20」이었는데,
한국어 「~하지 않고」 하나가 **〜ないで(동작)와 〜なくて(이유)** 로 갈리는 자리가 남아 있었다.
대응이 없는 것은 짝으로 세운다는 ⑥편 이후의 방침대로 `pair`를 꺼냈다.
정중↔보통(ません/ない), 현재↔과거(ない/なかった), ある↔いる도 같은 손으로 붙였다.

**어간이 앞으로 가는 곳을 미리 적었다.** 買わ + れる(⑯ 수동) · 買わ + せる(⑰ 사역) · 行か + なければ(㉑ 의무).
⑧편에서 より·ので를 뒤 편으로 넘긴다고 본문에 적어둔 것과 같은 이유 — 그 편을 쓸 때 되돌아올 자리가 생긴다.

**검증** — key 1235개 중복 0, 예문 1142개(한자 포함 1117) 정렬 실패 0.
쪽 넘침은 여섯 크기 두 모드 전수 검사로 **미덮임 0**. 경계 폭(500·699·700px)도 같이 훑었고,
17번에 적은 ⑤편 1px 두 건이 **쪽 번호까지 그대로** 남아 있는 것만 확인했다 — 이번 변경과 무관하다.

### 19. 문법 ⑩ 보통형 — 그리고 오래 미뤄둔 쪽 나눔 버그를 잡았다

**새 카드 타입 없이 `adjc`를 그대로 썼다.** 로드맵이 예상한 대로였다.
⑤편의 표는 정중형(高いです)이었고 ⑩편의 표는 보통형(行く / 行かない / 行った / 行かなかった)이다.
칸 수가 자유라 동사 12 · 형용사 4 · 명사 4에 전부 맞았다. 설명 14장 + 표 20장, **로드맵 그대로**.

**adjc key가 `adjc|단어|읽기`라 ⑤편과 부딪힐 뻔했다.** `conj`에는 `say`가 있어 강의별로 갈리는데
`adjc`에는 그런 칸이 없다. 高い를 ⑩편에 다시 쓰면 ⑤편 카드와 key가 같아진다.
그래서 **⑤편에 없는 형용사만 골랐다**(面白い · 暑い · 簡単 · 大切). 코드를 건드리지 않는 쪽을 택한 것이다.

**이 편이 가르치는 건 사실상 「새로 외울 게 없다」는 사실이다.**
사전형은 단어장에 있고, ない형은 ⑨편에서 만들었고, **た형은 て형의 て를 た로 바꾸면 끝**이고,
과거 부정은 ない에 なかった를 얹은 것이다. 진짜 새것은 명사·な형용사의 だ/じゃない/だった/じゃなかった 하나뿐이다.

**정중형을 못 쓰는 자리를 못 박았다.** 「行きますと思います」가 안 되는 이유 —
정중함은 문장 끝에서 한 번만 표시하고 문형 앞자리는 보통형이 채운다.
보통형은 「반말을 하기 위한 것」이 아니라 **문장 안쪽을 채우는 부품**이라는 것이 이 편의 결론이다.

#### 쪽 나눔 버그 — 15·16번에 「따로 다뤄야 한다」고 미뤄둔 그것

⑩편을 넣자 **1920×1000에서 문법 146쪽이 2px 넘치는데 `.scrollable`로 안 덮이는** 쪽이 생겼다.
설명 카드 두 장이 붙은 쪽이었다. 조용히 잘리는 자리라 그냥 둘 수 없어 원인을 팠다.

**원인** — `paginate()`가 항목 높이를 `offsetHeight`로만 재는데, 여기엔 margin이 안 들어간다.
그걸 `avail`에서 **4px을 빼는 것**으로 뭉뚱그리고 있었다. 그런데 여백이 있는 카드는 `.entry.note`(margin 2px)뿐이고,
`.entry.note`가 n장 이어지면 실제로 필요한 여백은 `2×(n+1)`이다. **n=1일 때만 4px이 맞고, 2장부터 모자란다.**
④편 63쪽 3px(15번)도, ⑤편 1px 두 건(17번)도 전부 같은 뿌리였다.

**고친 방식** — 뭉뚱그리던 4px을 걷어내고 **여백을 실제로 재서 더한다.**
항목마다 `marginTop`·`marginBottom`을 같이 재고, 맞닿은 여백은 겹친다는 것(margin collapsing)을 `Math.max`로 반영했다.
`avail`에는 반올림 오차분 2px만 남겼다.

**뜻밖의 덤 — 1366×768에서 단어 480쪽이 331쪽으로 줄었다.**
이 크기에서 지면 안쪽 높이가 537px이고 단어 카드가 178px이라 **셋이 딱 534px로 들어간다.**
그런데 옛 `avail`은 533px이라 1px 차이로 셋째를 밀어내고 **매 쪽 181px씩 비워두고 있었다.**
단어 카드 높이가 거의 균일해서 같은 계산이 책 전체에 되풀이됐고, 그래서 쪽수가 1.45배로 부풀어 있었다.
**2px 바꾼 결과치고 큰 변화라 의심스러워서, 옛 `paginate()`만 되돌린 사본을 따로 만들어 같은 크기에서 A/B로 확인했다**
— 데이터·화면은 같고 쪽수만 480 ↔ 331로 갈렸다. 새 쪽에서 넘침은 0이다.

**검증** — key 1270개 중복 0, 예문 1162개(한자 포함 1137) 정렬 실패 0.
쪽 넘침은 1920·1366·768·844×390·390×844·320×568 여섯 크기 두 모드에서 **미덮임 0**,
경계 폭 500·699·700px에서도 **미덮임 0**. **17번에 적어둔 ⑤편 1px 두 건이 이 수정으로 같이 사라졌다.**
좁은 화면에서 넘치는 쪽은 여전히 전부 `.scrollable`로 덮여 있다.

### 20. 문법 ⑪~⑮ — N5를 닫고 N4로 넘어갔다 (다섯 편을 한 번에)

**⑪ て형 활용 · ⑫ 비교와 정도**로 N5 문법이 전부 들어왔고, **⑬ 가능형 · ⑭ 의지형·명령형 · ⑮ 조건형**이 첫 N4 세 편이다.
섹션에 `lv:"N4"`만 붙였더니 목차의 N4 묶음이 「준비 중」에서 3편으로 바뀌었다 — 7편에서 깔아둔 구조가 그대로 작동했다.

| 편 | 설명 | 활용 | 짝 | 표 |
|---|---|---|---|---|
| ⑪ て형 활용 | 14 | 18 | 6 | — |
| ⑫ 비교와 정도 | 12 | — | 9 | 6 |
| ⑬ 가능형 | 12 | 16 | 6 | — |
| ⑭ 의지형·명령형 | 13 | 18 | 6 | — |
| ⑮ 조건형 | 14 | 6 | 8 | 11 |

**⑮의 새 카드 타입은 결국 안 만들었다.** 로드맵이 「⑮ 시작 전에 결정할 것」으로 남겨둔 항목이었다 —
`pair`가 2열 고정이라 조건형 넷을 한 장에 못 담는다는 것. **`adjc`를 그대로 썼다.**
`forms`의 칸 수가 자유라 `[["と","押すと","おすと"],["ば","押せば","おせば"],…]` 네 칸이 그냥 들어간다.
라벨 칸이 と·ば·たら·なら를 받고, `hit`으로 예문에 쓰인 형태 하나가 강조된다.
**⑳ 추측 다섯 종류도 같은 손으로 덮인다.** 로드맵의 「두 편이 훨씬 짧아진다」는 걱정이 코드 수정 없이 해소됐다.

**adjc key 충돌은 이번에도 단어를 골라서 피했다.** ⑫는 ⑤·⑩에 없는 형용사(大きい·長い·強い·広い·重い·親切),
⑮는 없는 동사(押す·曲がる·降る·急ぐ·休む·使う·開ける·勉強する)를 썼다. **19번에 적어둔 「셋째 강의가 또 표를 쓰면」이 이번인데,
`w`를 갈아 끼우는 것만으로 셋째·넷째 강의까지 버텼다.** 다섯째가 오면 그때는 key에 칸을 둔다.

**⑬ 앞에 N4 부(部) 표지를 세웠다.** 강의 표지와 같은 `cover` 카드인데 `no:"PART 2"`, `t:"N4"`로 두고
⑬~㉖ 열네 편을 한눈에 늘어놓았다. 펼침면 왼쪽에 부 표지, 오른쪽에 ⑬편 표지가 나란히 선다.
**그 바람에 한 섹션에 표지가 둘이 되어 key가 겹쳤다** — `cover|si`뿐이었기 때문.
`cover|si|j`로 바꿨다. 표지는 책갈피도 예문 캐시도 없어 실제 피해는 없었지만, 중복 검사에 걸리는 상태로 두지 않았다.

**설명 카드의 `**강조**`가 여태 화면에 별표로 찍히고 있었다.** ⑨편부터 본문에 `**`를 써왔는데 `noteHTML`은 `esc()`만 하고 끝이라
「**わ**로 바뀐다」가 별표째 나오고 있었다. `emph()`를 하나 두고 **이스케이프를 먼저, 별표 치환을 나중에** 걸었다 —
순서가 반대면 데이터의 `<`·`&`가 그대로 새어나간다. 새 다섯 편만이 아니라 ⑨·⑩편의 강조도 같이 살아났다.

**앞 편이 뒤 편을 줄여준 사례가 또 늘었다.** ⑬에서 만든 え단이 ⑭ 명령형과 ⑮ ば형에 그대로 쓰인다.
그래서 ⑮의 활용 카드가 6장으로 끝났다 — 만드는 법을 다시 가르칠 필요가 없었기 때문이다.
⑪은 ③편 て형 위에 얹기만 했고, ⑮의 たら는 ⑩편 た형에 ら를 붙인 것이라 새 활용이 아니다.

**검증** — key 1451개 중복 0, 1920×1000 문법 252쪽 전수 검사에서 **미덮임 0**.
`node --check`로 `<script>` 블록 전체 구문 확인, `**` 짝 안 맞는 곳 0, 설명 카드 밖에 쓰인 `**` 0.
