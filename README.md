# Kangi — JLPT N5 단어장

브라우저에서 책처럼 넘겨 읽는 일본어 N5 단어장. 파일 하나로 돌아간다.

상단바의 **「단어 / 문법」** 으로 두 권을 오간다. 각각 목차·쪽수·읽던 위치를 따로 갖는다.

- **단어 902개** / 23개 주제
- **문법 강의 4편** (단어와 별도) — 동사 활용 〜たい · 〜て형 · 자동사/타동사, 형용사 활용 い/な.
  설명 카드 50 + 변환 카드 36 + 짝 14쌍 + 형용사 활용표 18
- 모든 단어에 읽기 · 한국어 뜻 · 품사 · 예문 3줄(일본어 / 히라가나 / 해석)
- 일본어 발음 재생, 즉시 검색, 목차, 책갈피
- **예문의 한자에 커서를 올리면 읽기가 뜬다.** 아래 히라가나 줄에서 해당 부분도 같이 밝아진다. 터치 기기는 눌러서 고정.

## 단어 추가하는 법

`index.html` 안의 `const DATA = [...]` 배열만 손대면 된다.

### 일반 단어
```js
{w:"食べる", r:"たべる", k:"먹다", p:"동사",
 e:"昼ご飯はもう食べましたか。",
 ek:"ひるごはんはもうたべましたか。",
 eo:"점심은 벌써 드셨어요?"}
```
`w` 단어 / `r` 읽기 / `k` 한국어 뜻 / `p` 품사 / `e` 예문 / `ek` 예문 읽기 / `eo` 예문 해석

### 새 주제
```js
{ t:"주제 이름", items:[ ...단어들 ] }
```

### 표지 (강의 시작)
**반드시 한 쪽을 통째로 차지한다.** 앞 쪽을 끊고 혼자 한 쪽을 쓴 뒤 새로 시작한다.
표지 쪽에는 러닝헤드를 그리지 않는다 (제목이 이미 크게 있으므로).
```js
{cover:true, no:"동사 활용 ②", t:"〜て형", sub:"~하고 · ~해서",
 lead:"한 문단짜리 소개",
 bullets:["이 강의에서 다루는 것", "…"],
 meta:"설명 13장 · 동사 20개"}
```

### 짝 카드 (타동사 ↔ 자동사)
예문이 둘이므로 `exHTML`에 항목당 서로 다른 캐시 키가 들어간다 (`key+'|tr'`, `key+'|itr'`).
```js
{pair:true, hint:"〜ける / 〜く",
 tr: {w:"開ける", r:"あける", k:"열다",   e:"…", ek:"…", eo:"…"},
 itr:{w:"開く",   r:"あく",   k:"열리다", e:"…", ek:"…", eo:"…"}}
```

### 문법 설명 카드
```js
{note:true, t:"제목",
 p:["문단1", "문단2"],
 rows:[["行く","行き","行きたい"]]}   // 화살표로 이어지는 변환 예시
```

### 활용 변환 카드
단계 수는 자유다. 마지막 단계가 목표 형태로 강조된다.
```js
{conj:true, w:"行く", r:"いく", k:"가다", g:"1그룹 예외",
 steps:[{t:"行く", l:"기본형"}, {t:"行って", l:"いって"}],
 say:"いって",                       // 🔊로 읽어줄 발음
 e:"…", ek:"…", eo:"…"}
```
`g`에는 그룹과 규칙을 같이 적으면 좋다 (`"1그룹 む → んで"`).

### 형용사 활용 카드
네 형태를 표로 깐다. 칸 수는 자유지만 4개(현재·부정·과거·과거 부정)를 전제로 만들었다.
```js
{adjc:true, w:"高い", r:"たかい", k:"비싸다, 높다", g:"い형용사",
 hit:"高いです",                    // 예문에서 실제로 쓰인 형태 — 강조된다 (없어도 됨)
 forms:[["현재","高いです","たかいです"],
        ["부정","高くないです","たかくないです"],
        ["과거","高かったです","たかかったです"],
        ["과거 부정","高くなかったです","たかくなかったです"]],
 e:"…", ek:"…", eo:"…"}
```
각 칸은 `[라벨, 표기, 읽기]`. 🔊는 읽기(3번째)를 읽어준다.
key는 `adjc|단어|읽기`. **네 형태 전부 검색에 들어간다** — 「たかかった」로 쳐도 찾힌다.

칸 배치는 화면이 아니라 **지면 폭**이 정한다 (`repeat(auto-fit, minmax(178px, 1fr))`).
펼침면에서는 지면이 화면의 절반이라 미디어쿼리로는 맞출 수 없기 때문. 좁으면 알아서 한 줄씩 접힌다.

**주의 — `say`는 강의마다 달라야 한다.** 활용 카드 key가 `conj|단어|say`라서, 같은 동사가 여러 강의에 나올 때(買う가 〜たい에도 〜て형에도 있다) `say`가 겹치면 예문과 책갈피가 섞인다.
### 모드 (단어 / 문법)
섹션에 `kind:"grammar"`를 붙이면 **문법 모드** 쪽 책에 들어간다. 안 붙이면 단어 모드.

```js
{ t:"동사 활용 ② 〜て형", kind:"grammar", items:[ ... ] }
```

모드마다 쪽 나눔과 목차가 따로 계산되고, 읽던 위치도 `kangi-anchor-word` / `kangi-anchor-grammar`로 따로 저장된다. 검색과 책갈피는 두 모드를 함께 훑고, 다른 모드의 항목을 누르면 자동으로 그쪽으로 넘어간다.

**주의 — 같은 `w`+`r` 조합을 중복해서 넣지 말 것.** 책갈피 key가 `단어|읽기`라서 겹치면 하나를 찍을 때 다른 하나도 켜진다. 활용 카드는 `conj|` 접두사가 붙어 일반 단어와 안 겹친다.

## 만든 과정 · 결정 기록

시간순. 왜 그렇게 됐는지가 중요한 것들만.

### 1. 리스트형 단어장 (114단어)
플래시카드·가리기 없이 위에서 아래로 쭉 읽는 형태로 시작. TTS 발음, 주제별 목차.

### 2. 페이징 — 스크롤이 너무 길다
114개를 한 줄로 늘어놓으니 스크롤이 감당이 안 됐다. 책처럼 쪽을 나누고, 넓은 화면에서는 두 쪽 펼침.

처음엔 **10단어 고정**으로 했는데 여전히 쪽 안에서 스크롤이 남았다. →
**화면 높이를 실측해서 들어가는 만큼만 담는 방식**으로 바꿨다. 고정 개수로는 화면마다 안 맞기 때문. `overflow:hidden`이라 스크롤바 자체가 없다.

부작용: 총 쪽수가 기기마다 달라진다. 그래서 「읽던 위치」를 쪽번호가 아니라 **단어 key**로 저장하게 바꿨다.

**iframe 함정** — 창 `resize` 이벤트만 듣고 있었는데, iframe은 크기가 바뀌어도 이 이벤트가 안 온다(실측 0회). Artifact가 페이지를 iframe에 띄우므로 그대로 두면 내용이 잘렸다. `ResizeObserver`로 교체.

### 3. 색 — 네 번 갈아엎음
1. 베이지 + 테라코타 → 시스템이 다크 모드라 계속 어둡게 떴다. `prefers-color-scheme` 참조를 아예 제거하고 밝은 쪽을 기본으로.
2. 흰 종이 + 남색 → **순백은 책 같지 않다.** 종이는 순백을 안 쓴다.
3. 아이보리 → **눈이 편한 녹색으로.**
4. 세이지 녹색 → 색이 옅게 퍼져 흐릿했다. → **초록을 껍데기(상단바·하단바·책상)에 몰아넣고 지면과 글자는 중립색으로.**

최종: 껍데기 `#17795a`, 지면 `#f5f7f4`, 강조 `#00704a`.
**글자에는 색을 안 쓴다** — 예문 해석도 갈색에서 회색으로 내렸다. 색이 아니라 밝기 위계로 구분.

### 4. 902단어로 확장
23개 주제로 재편성. 이때 **책갈피 저장 방식을 순번 → 단어 key로** 바꿨다. 순번이면 단어를 끼워 넣는 순간 전부 어긋난다. 앞으로 N4를 얹어도 안 깨진다.

중복 7건을 잡아냈다. `本`이 「책」과 조수사 「~자루」로 겹쳐서 조수사를 `〜本`으로 분리.

### 5. 히라가나 가독성
예문 아래 히라가나가 잘 안 보였다. 12px인 것도 문제였지만 **투명도 85%를 덮어씌운 게 더 컸다.** 투명도를 걷어내고 14px로.

### 6. 검색 + 문법 강의
902개가 되면서 검색이 필수가 됐다. 가타카나↔히라가나를 맞춰 비교하고 예문 내용까지 훑는다.

〜たい 활용을 예시로 문법 강의 카드 타입(`note` / `conj`)을 새로 만들었다. 반응 보고 넓힐 예정.

이때 **360px 폭에서 상단바가 가로로 넘쳤다** — 검색 버튼이 늘어난 탓. 600px 이하에서는 버튼 글자를 숨기고 아이콘만 남기도록.

### 7. 문법을 별도 모드로 분리
처음엔 문법 섹션을 단어책 맨 뒤에 붙였는데, 성격이 다른 내용이 같은 흐름에 섞였다.
**「단어 / 문법」 두 권으로 분리.** 모드마다 쪽 나눔·목차·읽던 위치가 따로 간다.

검색과 책갈피는 **일부러 두 모드를 함께** 훑게 했다. 「たべたい」를 검색했는데 문법에 있다고 안 나오면 검색의 의미가 없다. 다른 모드 결과에는 「문법」/「단어」 태그가 붙고, 누르면 그쪽으로 자동으로 넘어간다.

모드 전환 버튼이 들어가면서 **상단바가 또 넘쳤다**(393px 필요 / 390px 화면). 브랜드의 N5 배지 → 420px 이하에서 브랜드 자체 순으로 단계적으로 줄였다. **모드 전환만은 끝까지 남긴다** — 없으면 문법에 갈 방법이 없다. 320px까지 확인.

전환 소요: 문법 7–12ms, 단어 155–164ms(902개 재측정).

### 8. 한자 읽기 — 올리면 보이게
예문마다 한자 문장(`e`)과 히라가나 문장(`ek`)을 둘 다 갖고 있다는 점을 이용했다.
**한자가 아닌 부분(가나·기호)은 양쪽에 똑같이 나타나므로** 그걸 기준점 삼으면 사이 구간이 곧 그 한자 덩어리의 읽기다. 사전 없이 순수 문자열 정렬로 해결.

- 한자 있는 예문 894개 **전부 정렬 성공, 실패 0건.** 한자 덩어리 1939개에 읽기가 붙었다.
- 덩어리 단위까지만 나눈다. `毎朝散歩 = まいあささんぽ` 처럼 붙어 있는 건 못 쪼갠다 — 그러려면 사전이 필요하고, 없는 걸 있는 척하느니 덩어리째 보여주는 게 정직하다.

**말풍선은 절대 위치로** 띄운다. 줄 높이를 건드리면 쪽 나눔이 흔들리기 때문. 아래 가나 줄의 대응 부분을 같이 밝히는 건, 긴 가나 중 **어디가 이 한자인지**가 곧바로 보이게 하려고 덧붙였다.

**성능(한자 읽기)** — 스팬 1939개가 늘면서 재분할이 165 → 240ms로 느려졌다.
캐시를 넣어도 그대로였다. 병목은 정렬 계산이 아니라 **측정용 DOM이 무거워진 것**이었다.
그래서 쪽 높이를 잴 때는 스팬 없는 평문으로 그린다. 스팬이 인라인이고 여백이 없어 높이에 영향이 없다는 걸 **928개 전수 비교로 확인**한 뒤에 적용했다 (차이 0건). 결과 143–154ms — 기능 넣기 전보다 오히려 빨라졌다.

### 9. 문법 ② 〜て형 — 카드 구조 일반화
〜たい 카드는 「기본형 → ます형 → たい형」 3단계가 코드에 박혀 있었다. て형은 2단계라 안 맞아서 **`steps` 배열로 일반화**했다. 기존 16장도 같은 형태로 옮겼다.

**키 충돌 버그** — 넣고 나니 買う의 て형 카드에 たい 예문이 나왔다.
활용 카드 key가 `conj|단어|읽기`였는데, 買う는 두 강의에 다 있으니 **키가 같았다.**
예문 캐시가 앞선 것을 돌려주고 있었고, 책갈피도 서로 섞이는 상태였다.
key에 목표 형태(`say`)를 넣어 해결 — `conj|買う|かって` vs `conj|買う|かいたい`.
고친 뒤 961개 key 전수 유일성을 확인했다.

검색 결과도 두 카드가 「買う 사다 활용」으로 똑같이 보여 구분이 안 됐다. 활용 카드는 뜻 대신 **목표 형태**를 보여주도록 바꿨다 — `買う → 買って`.

### 10. 강의 표지
강의가 둘이 되니 쭉 이어져서 어디서 갈리는지 분간이 안 갔다.
**표지 카드**를 넣어 강의마다 한 쪽을 통째로 쓰게 했다. 넘기다 보면 새 강의 시작이 바로 보인다.

쪽 나눔 규칙에 예외를 하나 추가했다 — 표지를 만나면 진행 중인 쪽을 끊고, 표지 혼자 한 쪽을 쓰고, 새 쪽으로 넘어간다.

짧은 화면(320×568)에서 표지가 1px 넘쳤다. flex 중앙정렬의 반올림 아티팩트라 실제로 잘리는 건 없었지만, `max-height:580px` 구간을 추가해 여유를 57px로 벌렸다.

### 11. 단어에도 표지 · 모바일 대응

**단어 23개 주제에도 표지를 넣었다.** 문법 표지가 「무엇을 배우는지」를 적는다면, 단어 표지는 「무엇이 들어 있는지」를 보여준다 — 한 줄 소개 + 대표 단어 4개를 칩으로.

**번호 문제** — 표지를 항목 배열에 넣으면 단어 번호(001~902)가 전부 한 칸씩 밀린다.
표지·설명·활용 카드를 빼고 '진짜 단어'만 세는 별도 번호(`n`)를 만들었다. 목차의 번호 범위와 러닝헤드도 이 번호를 쓴다.

**펼침 기준을 1000 → 700으로 낮췄다.** 폰 가로(844×390)에서 한 면만 쓰면 넓은 화면에 단어 하나만 남아 낭비였고, 태블릿 세로(820)에서는 한 줄이 100자를 넘어 읽기 나빴다. 두 쪽이면 한 면이 320px 이상 확보된다.

**세로가 짧은 화면** — 390px 중 상·하단바가 105px를 먹어 읽을 자리가 없었다.
`max-height:480px` / `400px` 두 단계로 껍데기와 항목을 조였고, 표지는 미리보기·목록을 접는다.

**안전장치** — 아무리 조여도 항목 하나가 쪽보다 큰 화면은 있을 수 있다. 그런 쪽에만 `.scrollable`을 붙여 스크롤을 연다. 조용히 잘리는 것보다 낫다. (현재 확인한 모든 크기에서 0건)

**터치 대응** — `:hover` 규칙을 전부 `@media (hover:hover)`로 옮겼다. 터치에서는 탭한 뒤 hover가 남아 눌린 것처럼 보이기 때문. 한자 툴팁은 `:hover`와 `.on`(탭 고정)을 분리해야 했다 — 합쳐두면 탭 경로까지 죽는다. `@media (pointer:coarse)`로 아이콘 버튼 24→30px 등 표적도 키웠다.

**되짚은 버그 ①** — 320px에서 한 쪽이 9px 넘쳤다. 원인은 가나 강조 스팬 `.kr`의 좌우 패딩 1px. 인라인 스팬의 가로 크기가 달라져 줄바꿈이 바뀌는데, 쪽 높이는 평문으로 재고 있으니 어긋났다. 패딩을 없애고 배경만으로 강조하도록 바꾼 뒤 260~740px 일곱 개 폭에서 986개 항목의 평문/렌더 높이가 전부 일치함을 확인했다.

### 12. 문법 ③ 자동사·타동사 — 그리고 오래 숨어 있던 버그

대조를 보여줘야 해서 **짝 카드(`pair`)** 를 새로 만들었다. 활용 카드는 변환 체인이라 안 맞았다.
타동사(を)와 자동사(が)를 위아래로 놓고 각각 예문을 붙인다. 예문이 둘이라 `exHTML`이 항목당 캐시 키를 둘 받도록 고쳤다.

**측정 폭이 렌더 폭과 달랐다 (오래된 버그)**
`paginate()`가 빈 틀을 **한 쪽만** 깔고 높이를 쟀다. 그런데 펼침면에서는 **두 쪽**으로 그려진다.
즉 1178px에서 재고 589px로 그리고 있었다. 폭이 절반이면 줄바꿈이 늘어 실제 높이가 커진다.

단어 카드는 짧아서 우연히 안 걸렸고, 화면에 보이는 두 쪽만 검사해 왔기 때문에 계속 지나쳤다.
이번 강의의 설명 카드가 길어지면서 63px·23px씩 넘쳐 드러났다.

고친 뒤 **전 쪽 전수 검사**로 확인했다 — 데스크톱·노트북·폰 세로·작은 폰에서 두 모드 모두 넘침 0.
폰 가로 문법 모드에서만 37쪽이 넘치는데, 설명 카드가 224px 높이보다 커서 생기는 것이고 **전부 `.scrollable` 예외로 덮여 있다**(미덮임 0). 잘리는 내용은 없다.

**교훈** — 「보이는 쪽만 검사」로는 부족하다. 이후로는 빈 틀을 깔고 전 쪽을 훑는 방식으로 검사한다.
표지 쪽(`display:flex`)을 측정 컨테이너로 쓰면 프로브가 가로로 배치돼 결과가 엉킨다는 것도 같이 알았다.

### 13. 문법 ④ 형용사 활용 — 그리고 깃 저장소

동사만 세 편이 이어져 있어서 형용사로 넘어갔다. 규칙 계통이 아예 달라 커버 범위가 크게 넓어진다.
설명 14장 + 형용사 18개. 둘을 가르는 법, 「高いでした」가 없는 이유, いい 불규칙,
〜くて/〜で 잇기, 〜く/〜に 부사, 〜くなる/〜になる 변화까지.

**새 카드 타입 `adjc`** — 형용사의 네 형태는 서로 유도되는 게 아니라 나란히 놓인 선택지다.
동사 활용 카드(`chain`)는 「기본형 → 중간형 → 완성형」이라 화살표가 맞지만 여기엔 안 맞아서, 표로 깔았다.
칸 접힘을 화면 폭이 아니라 지면 폭이 정하게 한 이유는 12번에서 배운 것과 같다 —
**펼침면에서 지면은 화면의 절반이다.** 미디어쿼리는 그걸 모른다.

**같이 고친 것 둘**
- 설명 카드 rows에 `"→"`를 직접 넣은 곳들. 렌더러가 칸 사이에 화살표를 이미 넣기 때문에 두 개가 겹쳐 나왔다. 12개 제거 (〜て형·자동사 강의 포함).
- 짝 카드를 책갈피에 넣으면 목록에 `undefined`가 찍혔다. 짝 카드에는 `w`·`k`가 없고 `tr`·`itr`로 들어있다. `開ける ↔ 開く 「타/자」`로 나오게 고쳤다.

검사는 12번에서 정한 방식대로 — 빈 틀을 깔고 전 쪽 전수 검사.
1920·1366·768·390·320·844×390 여섯 크기, 두 모드 전부 **미덮임 0**.
좁은 화면에서 넘치는 쪽은 전부 `.scrollable`로 덮여 있다.

이 시점에 GitHub(`kes-knows-nothing/kangi`)에 올렸다. 코드 보관 겸, 나중에 Pages로 바로 배포하기 위해.
